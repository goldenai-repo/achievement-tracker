# Cloud data artifacts

The geography data is deliberately split into two deployment targets:

1. `catalog_entities.jsonl` is imported into Cloud SQL. It contains the
   application-owned country/admin1 IDs, names, parent relationships, center
points, and persisted map bounds.
2. `boundaries/*.geojson` is copied to Cloud Storage. These are public,
   read-only ADM1 assets consumed by MapLibre; they should not be bundled into
   the Android APK.

The current local catalog is still the working catalog table. The boundary
artifact is source-agnostic, so a future geoBoundaries-only catalog importer
can replace the catalog generation stage without changing the Cloud SQL or
Cloud Storage deployment format.

The geoBoundaries-only local profile is generated by
`scripts/download_geoboundaries_catalog.py`. It uses ISO-3-based application
IDs such as `country:CHN` and `admin1:CHN-shanghai-municipality`; this is a new
catalog identity space and should be migrated deliberately if existing user
check-ins use the older GeoNames IDs.

Catalog metadata stores both the complete geometry bounds (`full_bounds`) and
the default map viewport bounds (`bounds`). The latter is calculated from the
largest polygon component, preventing remote islands or antimeridian-spanning
territories from forcing a country view to world scale. The complete GeoJSON
asset remains unchanged and available for future “show all territory” views.

## Build the geoBoundaries-only local catalog

From `backend/`:

```bash
python -m scripts.download_geoboundaries_catalog \
  --raw-dir ../data/raw/geoboundaries \
  --normalized-dir ../data/normalized/geoboundaries \
  --source-version geoBoundaries-current-gbOpen \
  --max-workers 8
```

The canonical-name override file is
`backend/data/geoboundaries_overrides.json`. It preserves the provider
`shapeName` in GeoJSON metadata while exposing `Guangdong` as the application
name and assigning `admin1:CHN-guangdong`.

Import the generated catalog into a separate local database while validating
the migration:

```bash
DATABASE_URL=sqlite:///../data/achievement_tracker_geoboundaries_migrated_v2.db \
python -m scripts.import_catalog_artifact \
  --artifact ../data/normalized/geoboundaries/catalog_entities.jsonl
```

Run FastAPI with this profile by setting `DATABASE_URL` and
`BOUNDARY_DATA_DIR=../data/normalized/geoboundaries/boundaries` in the local
environment. The existing GeoNames-backed database is intentionally left
untouched until check-in ID migration is reviewed.

## Migrate existing check-ins

After importing the new catalog into the target database, run a dry run first:

```bash
python -m scripts.migrate_checkins_to_geoboundaries \
  --source-database-url sqlite:///../data/achievement_tracker.db \
  --target-database-url sqlite:///../data/achievement_tracker_geoboundaries_migrated_v2.db \
  --report ../data/reports/geoboundaries-migration-dry-run.json \
  --dry-run
```

The migration maps country IDs by ISO-3 metadata and admin1 IDs by normalized
name/suffix matching. It preserves users, check-in IDs, dates, notes, deleted
records, and rebuilds unlock aggregates. It stops if a check-in cannot be
mapped; review the report before using `--allow-unmapped`.

## Generate artifacts locally

From `backend/`:

```bash
python -m scripts.prepare_cloud_artifacts \
  --boundary-dir ../data/normalized/geoboundaries/boundaries \
  --output-dir ../data/cloud-artifacts \
  --source-version geoBoundaries-current-gbOpen
```

Optional production URLs can be embedded in catalog metadata:

```bash
python -m scripts.prepare_cloud_artifacts \
  --boundary-dir ../data/normalized/geoboundaries/boundaries \
  --output-dir ../data/cloud-artifacts \
  --boundary-base-url https://storage.googleapis.com/<bucket>/boundaries \
  --source-version geoBoundaries-current-gbOpen
```

The output includes `manifest.json`, SHA-256 checksums, feature counts, and
unmatched boundary feature names. Review the manifest before deployment.

## Validate/import the catalog

Validate without changing the database:

```bash
python -m scripts.import_catalog_artifact \
  --artifact ../data/cloud-artifacts/catalog_entities.jsonl \
  --dry-run
```

Import into the database selected by `DATABASE_URL`:

```bash
python -m scripts.import_catalog_artifact \
  --artifact ../data/cloud-artifacts/catalog_entities.jsonl
```

For Cloud SQL, run the same command with the production `DATABASE_URL` and
the Cloud SQL Connector/proxy configuration used by the deployment. The
import is idempotent by the application-owned catalog ID.

## Upload boundaries to Cloud Storage

After authentication and bucket creation:

```bash
gcloud storage cp \
  ../data/cloud-artifacts/boundaries/*.geojson \
  gs://<bucket>/boundaries/
```

The bucket objects need a stable HTTPS URL reachable by the Android client.
MapLibre's GeoJSON source cannot attach the app's bearer token, so boundary
objects should be public read-only assets or served through a separate public
CDN/asset endpoint. User check-ins remain authenticated through FastAPI.

Keep the `manifest.json` and the geoBoundaries attribution with the release;
geoBoundaries gbOpen data is CC-BY 4.0.
